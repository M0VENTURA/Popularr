This sheet is the single answer, and the caller only varies its SCOPE. ── USAGE ───────────────────────────────────────────────────────────────── {% set scan_scope_kind = 'library' %} {% include 'components/_scan_modal.html' %} ``scan_scope_kind`` is one of ``library`` / ``artist`` / ``album``. Adding a page is a row in that table, not a new sheet. ``library`` is the only scope wired today, because that is the dashboard's — the artist and album scopes are the next slice and their form endpoints are already known (``scans.scan_artist_custom`` / ``scans.scan_album_custom``). {# These two are NOT the same reset, and the help text says so — the difference is the thing users get wrong: Force — carry on from here, but ignore the skip windows/cache. Restart — go back to the top. With BOTH ticked you get a forced run from the beginning. Both are DISABLED (with a reason) for a type that ignores them, rather than hidden. Hiding would make the list jump around as the selection changes, and a reader cannot compare options across types if they vanish; a disabled control states "this does not apply" where a hidden one says nothing. #}
