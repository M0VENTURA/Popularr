{# ═══════════════════════════════════════════════════════════════════════ THE log viewer — one viewer, opened from the status bar's ticker or the System ▸ Logs menu item, on top of whatever page the user is on. ═══════════════════════════════════════════════════════════════════════ CONSOLIDATION (2026-10-14). This app had TWO log views showing the same data: the dedicated /logs page and this modal. The page's route now redirects here (test_site mode), and every control it owned moved in: * the FILE PICKER — ``#logSelector`` used to be the page's dropdown listing unified_scan.log / access.log / …; the modal's five source tabs (Scanner / Queue / Soulseek / Navidrome / System) mapped onto five of those same files. Both are ONE control now: a picker whose options carry the tab's label as the option text, populated by logs.js from ``GET /api/logs/list``. * the FILTER box (+ ``.*`` regex and ``Aa`` case modes) and the LEVEL toggles, sitting on top of the stream window so filtering never means scrolling away from the output it filters. * the WRAP toggle — ON by default. Long lines are the whole reason the horizontal scrollbar existed; both viewers suffered from it. The header is ONE row (title · picker · ⋮ · close). The old second row of five large tab buttons and the Download/Clear/Pause icon cluster are now a single ⋮ overflow menu, so the header costs ~40px instead of ~100px — which matters most on the phone this modal is opened from. ⚠️ EVERY ``id`` BELOW IS BINDABLE. logs.js's ``bind()`` silently skips a missing id, so a typo here is a button that does nothing — ``tests/test_log_viewer_filters_and_jump.py::TestIdsAgree`` asserts each one exists, and that file also pins the jump button's placement (outside the scrolling 
, inside a positioning context) and the badge's
  ``aria-hidden``.

  The page template this replaced stays on disk in this tree ONLY because
  the virtual workspace cannot delete files; it is unreachable (see
  ui_routes.logs). The live tree still has its own page + inline script.
#}
