{# THE SEARCH BOX, and which one is on screen depends on the breakpoint. At lg+ the TOP NAVBAR's field (`#navSearchInput`) is the entry point — `openUnifiedSearch()` focuses it back, so this box would be a second, redundant field. Below lg that navbar field is `d-none` (the mobile shell has no search row — see base.html), so it cannot be typed into, and this is the only field the user can reach. Hence `d-lg-none`: visible exactly when the navbar's is not. ⚠️ It used to be `d-none` unconditionally with `aria-hidden="true"` and `tabindex="-1"` — a pure MIRROR of the navbar field that was never meant to be typed into. That was correct only for as long as the navbar field was on screen at every width. Hiding the navbar field below lg left the flyout with NO usable box at all: the modal opened, and there was nowhere to type. `aria-hidden` and `tabindex="-1"` are therefore gone. They were there to keep a permanently-hidden element out of the accessibility tree and the tab order; `display: none` at lg+ already does both, and on a visible element `aria-hidden` would be a violation (it hides a real control from assistive tech). #} {# ⭐ THE FIELD AND THE FILTER ICON SHARE ONE ROW. They were two rows: the field, then the scope chips with the ▽ funnel pushed to their right. On a phone that spent a whole extra row's height on a control strip before any result appeared, and the funnel read as belonging to the CHIPS rather than to the query — which is what it filters. ⚠️ The ▽ keeps NO `d-lg-none`. At lg+ the navbar field is the entry point and this whole row would vanish with it, taking the only release-type filter with it — so the button stays visible at every width and `ms-auto` parks it at the panel's right edge on its own line there. A hidden control is a lost feature; a lone icon on a line is a layout, and this is the layout that keeps it reachable. #}
These filters apply to both your local Library and MusicBrainz discovery.
