{# Sign-in page — STANDALONE, deliberately not extending base.html. It is rendered before a session exists and must not pull in the app shell (navbar, global search modals, player bar, the unified log modal). That is why it carries its own , its own Bootstrap s and its own stylesheet rather than the base layout. Because it does not extend base.html it also does not get popularr.css, so css/login.css declares the theme tokens locally — see the note in that file. The stylesheet is linked with url_for('static', …) rather than versioned_static('css/…'): this template sits OUTSIDE base.html, so it does not rely on the base layout's conventions, and — more importantly — the `versioned_static` helper and the `dist` paths below must keep working when `features.use_local_assets` is on, exactly as the original did.
